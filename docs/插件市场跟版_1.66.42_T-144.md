### 裁决

- **直接跟到 1.66.42，而不是停在 1.66.40/41** — 1.66.42 同时包含 carrier 安装树判定与陈旧 release 修复，且与 1.66.41 同批发布；停在中途会失去本轮最相关的两项稳定性修复 — 错判代价：1.66.42 的 UI/判定变化一起进入发行版。
- **`undici` 不升级** — 1.66.42 的依赖范围仍是 `^7.29.1`，现随包 7.29.1 已满足；无证据表明需要换版本 — 错判代价：若上游后续要求更高版本，需再走一次 vendor 跟版。
- **修正第三方声明里的旧 `@worknexus/*` 描述** — T-143 已把企业层迁出本仓，继续生成「13 个包」会向用户交付错误声明；本次只改声明生成器文案，不触碰上游代码 — 错判代价：差异集 14 补丁字节数变化，需重新登记（已登记）。
- **出包重试改用 npmmirror registry** — 首次重出包在 `runtime:install` 连接 npmjs 10 分钟无下载增长后挂起，已终止并清理；改用镜像后同一把锁文件与完整性校验通过 — 错判代价：镜像不可用时需回退 npmjs 并重试。

## 4. 未验证项与边界

- **需真机复核（B 类）**：真实 profile 上点击插件「更新」并重启，确认版本保持；市场页品牌图标、carrier 插件不再被误删、陈旧 release 不再展示、profile 锁恢复路径的实际表现。
- **需外部输入（C 类）**：上游声明的 DSH `0.2.1-rc.2` Web 测试 57/57 由上游执行，本轮未在本地重跑；三个目标插件版本与 rc.2 的兼容性仍由市场自身兼容性检查判定。
- **环境边界**：上游全量 `pnpm run test` 在本会话无法形成有效结论——本会话没有系统 `git`，且非提升权限下符号链接用例失败，lefthook/git/symlink 相关用例报环境错误；本任务以 `typecheck` 5/5、`lint` exit 0、打包 build gates 9/9、运行时 smoke 与专项门禁为准。
- **既有边界**：预置插件版本向前同步仍只改 `package.json` 与 `node_modules`，`pnpm-lock.yaml` 可能落后一版，直到下一次成功的市场操作由 pnpm 重写；本轮未改启动路径的锁文件策略。
- **超出本次范围**：企业层功能、公开镜像发布、自动更新 feed 演练。
- **本次未改**：上游会话执行、工具调用、插件加载、更新算法、恢复策略、安全基线。
