## 3. 上游测试期望文件的处置（全局裁决，适用 02/03 及其后所有品牌相关差异）

**裁决：就地更新上游期望文件** —— 在 `repos/deepseek-harness` 内直接更新受影响的上游期望文件与内联断言（品牌名相关的期望值），并把该改动固化为对应差异集补丁；**不采用企业侧 overlay**。

- **理由**：① 上游桌面壳测试套件是本项目唯一可运行的客户端回归网（实测 116 文件 / 1326 用例 / 约 17 秒），overlay 会让上游套件永远不能原样跑绿，必须再维护一套 runner 与期望集；② AGENTS §6 要求上游既有测试不得删除或跳过——就地更新改的是**期望值**而非测试逻辑，套件仍在原地、仍被执行；③ 受影响的失败全部由**已批准的白名单差异**（1.1 产品名与标识）引起，属差异的必然推论，更新期望值是最小、最可枚举、最可 rebase 的处置。
- **错判代价**：改为 overlay → 每次上游升级都要重放映射，且套件在本仓库永远不可直接运行，「回归网」名存实亡；就地更新但不登记 → 违反 AGENTS §3，下一次上游同步会把我们的期望值当冲突误删。
- **实测范围**：截至 2026-09-29，该裁决涉及上游 `apps/desktop/tests/**` 中 **10 个文件、31 条失败用例**（品牌相关），清单见 `内部验收证据（RM-01_上游桌面壳测试基线）`。
- **T-107 执行记录（2026-09-30）**：客户端侧已按本裁决就地更新 **16 个**期望文件（14 个 `tests/expected/*.txt` + 2 个 spec 内联期望），品牌相关套件 4 文件 / 116 用例全绿；`apps/desktop/tests/**` 中的 **1 个**文件（`expected/about-panel.json`）因 S5 的关于页源码改动随本批更新，余 **9 文件 / 26 用例** 留给 T-108 重新枚举。**判据边界**：`verify_t028_release.py` 的 R6 由「任何 `tests/` 改动即失败」改为「未删除测试文件 + 未新增 skip/todo + 未增删用例声明」，与该裁决一致（其余断言不放宽）。

## 4. 与需求书 §13.3 的关系

**裁决：差异集条目变化登记在本文件，不回写需求书 §13.3** —— 理由：§13.3 是「与官方设计冲突时需求让位」的登记表，差异新增不是需求让位（没有哪一条需求被官方设计顶掉）。二者不得混用，否则 §13.3 会退化成流水账。
