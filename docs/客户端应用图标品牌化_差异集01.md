## 5. 裁决记录

| # | 裁决：<决定> — <理由> — <错判代价> |
| --- | --- |
| A-1 | **图标版式取「浅色圆角砖图 + 居中标志」**（而不是纯标志透明底） — ①上游 Windows/macOS 图标本就是「砖图 + 图形」，等位替换不改变图标在任务栏/资源管理器中的体量感；②标志含近白色花瓣，透明底在浅色壁纸上会「缺一块」，砖图的浅灰渐变面（沿用安装器 lockup 的 `#FFFFFF → #EDEFF3`）给它边界；③与安装器/欢迎窗的既有品牌面同色系 — 若决策人偏好纯标志透明底，改一处几何常量重生成即可（代价：一次重生成 + 一次门禁复跑） |
| A-2 | **矢量源用「内嵌 base64 标志」而非重画矢量** — 正式素材只有位图（决策人 2026-09-30 提供 8000×4500 PNG，仓库内以 128×128 内嵌为单一来源）；重画必然与原稿产生偏差，且违背「标志不重画」的既有口径（差异集 13 同款处置）。`icon-windows.svg` 因此仍是**上游托盘渲染器可用**的源（V-7 实证） — 若日后拿到矢量标志，替换内嵌位图即可（代价：一次重生成） |
| A-3 | **生成器自持（PowerShell + GDI+），不把上游 `render:tray-icon` 当提交产物的生产路径** — ①仓库既有的品牌素材生成器（`make_brand_assets.ps1`）就是同款形态，门禁可断言「确定性重生成且逐字节一致」；②上游渲染路径依赖 `node_modules`（sharp），会让门禁与素材复现绑在依赖安装态上 — 代价：生成器需自跟上游 `TRAY_ICON_SIZES` 与 1.2× 放大系数，已在脚本注释与门禁 G6 中标注看守点（上游改口径时门禁会亮红） |
| A-4 | **只重导出差异集 01 的图标 section，不重导整批 12 文件** — 工作区的 `electron-builder-config.mjs` 相对 HEAD 已有 15 行改动（含差异集 14 的 `extraResources` 第三行），若整批重导出会把**别的差异集拥有的 hunk**拉进 01，造成跨补丁重复（DS-8 明令同一文件不应出现在两个补丁里） — 若整批重导出，3-way 重放仍可过但审计口径会失真（代价：一次补丁重导 + 两处登记更新） |
| A-5 | **托盘 16px 不做单色降级** — 上游托盘一直是「彩色 brick 图」形态（原为鲸鱼 + 渐变），单色化属改设计语言而非换素材；且托盘提示与点击行为不变 — 若真机观感不可接受，作为 B-3 的后续增量处理（代价：一次素材增量 + 门禁复跑） |
