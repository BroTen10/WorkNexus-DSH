# 企业事件通道（T-033）

## 1. 结论先行

1. 企业事件通道是官方 Cordis 事件机制之上的**薄适配层**：发布调用官方 `Context.emit()`，订阅调用官方 `Context.on()`。
2. 适配层不保存事件、不排队、不维护第二套订阅表；`official` Context 由应用装配时注入，测试中的 Fake Context 仅用于验证官方接口形状。
3. 企业事件 topic 使用 T-030 契约的 `ent.*` 白名单（当前 6 项）；白名单外 topic 既不注册也不发布。
4. 单个订阅者抛错会被捕获并通过 `onError` 上报，不影响后续订阅者和官方事件分发。
5. 订阅返回的退订函数会调用官方 Cordis disposer；官方机制仍是唯一事件承载层。
6. 相比附录 B 的旧 `HostEvent.at` 形状，本实现沿用 T-030 契约的 `topic/occurredAt/payload`，并补上附录要求的 `source` 来源标记；以派发卡和 T-030 契约为准。

## 4. 未验证项与边界

**需真机复核（B 类）**

- B-1：真实 Cordis `Context` 的 `on()` disposer 形态和 `emit()` 多参行为需在锁定基线装配后复核；本任务按上游源码和测试使用 `ctx.on(topic, handler)` / `ctx.emit(topic, payload)`。
- B-2：真实企业事件源（identity / space / plugin / usage）接入时机未做；当前只冻结通道。

**需外部输入（C 类）**

- C-1：后续是否需要增加 `ent.*` topic 白名单，应随契约变更流程递增版本并留痕。

**超出本次范围**

- O-1：不实现持久化事件日志、跨进程事件分发、重放或背压队列。
- O-2：不订阅官方事件；官方事件到企业事件的映射归 T-032。
