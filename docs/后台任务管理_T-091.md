# 后台任务管理（T-091）

## 1. 结论先行

1. 控制面新增 `/api/v1/jobs`：创建（queued）、列表、单任务查看、取消、恢复、关闭；任务与**用户 / 空间 / 插件**三重关联（需求书 §4.6.1 功能 3）。
2. 权限：空间成员 + `session.create`（写）/ `space.read`（读）；未授权一律 404 并写 `denied` 审计（与 T-045/T-071 同口径）。
3. 状态变更全部入审计：`acp.job.start` / `acp.job.cancel` / `acp.job.resume` / `acp.job.close`（§6.2 第 4 类）。
4. `closed` 是新增终态：ACP 的「关闭会话」与「取消工作」语义不同，因此扩展 `BackgroundJob` 状态集合（迁移 `0005`），不用 `cancelled` 冒充关闭。
5. 后台任务不阻塞主界面：控制面所有接口都是短事务，**不代理 ACP 运行时**（执行由 T-090 适配层负责）；门禁断言控制面代码无 `jsonrpc` / `spawn` / `dsh --profile acp`。
6. 裁决：**恢复 = 重建会话并重放输入摘要**（T-091 派发卡默认值）——`resume` 只把任务置回 `queued`、累加 `resumes` 并保留 `inputSummary`，不假装恢复了远端会话内存态；`closed` 为终态，不可再恢复（返回 409）。
7. 裁决：`close` 幂等（重复关闭返回 `alreadyClosed: true` 而不报错）——理由是关闭是收敛动作，重复调用不应产生错误噪声 — 错判代价：调用方需读 `alreadyClosed` 才能区分「本次关闭」与「已关闭」。

## 4. 未验证项与边界

**需真机复核（B 类）**

- B-1：真实 ACP 会话与后台任务的状态联动（控制面只做台账，执行在 T-090 适配层）。
- B-2：GUI 任务列表的实时刷新与「不阻塞主界面」体验。
- B-3：`closed` 约束在真实并发迁移下的表现（与 T-041 B-1 同类）。

**需外部输入（C 类）**

- C-1：后台任务的默认模型/推理强度与超时策略。

**超出本次范围**

- O-1：不实现任务调度器/队列 worker（P6A 只要求创建、查看、取消、恢复、关闭）。
- O-2：不用后台任务替换普通用户的交互会话（§4.6.1 第 6 条）。
