# 问题记录：第三方侧边栏插件预览报 405（dsh-better-sidebar 半挂）

> **类型**：问题记录（**非**缺陷单；第三方插件 × 插件市场交互，未改任何代码/配置）｜ **登记**：2026-10-13
> **触发**：决策人点击会话内的 wiki 文件链接（`wiki/china-llm-market/agent-bidding-trend.md`），右栏预览显示裸红字 `HTTP 405`
> **现场**：WorkNexus-DSH 安装态（DSH `0.2.1-alpha.2`）｜ `DSH_HOME=C:\Users\<user>\.dsh`｜ Host 仅监听回环，端口每次重启变化（本例 10807 → 6247；重启后 `boot: plugin kept off: dsh-better-sidebar`）
> **当前状态**：机制与触发条件已定位，规避口径已落地；「未重启窗口里半挂」**未**在隔离环境复现

## 1. 结论先行

1. **不是文件、路径或权限问题**。被点的文件存在且正常；任何文件经同一条链路打开都会 405。
2. **也不是 DSH 自带文档预览的问题**。自带预览失败时显示 `读取失败：{message}`（`ui-sidebar-documentpreview` 的 zh 文案），裸 `HTTP 405` 是第三方插件的特征。
3. **根因是一条链**：该面板是第三方插件 `dsh-better-sidebar` 的编辑器 → 该插件**宿主半边未应用、浏览器半边仍在页面**（客户端清单只要求 entry 有 fiber，见 §2 E-4）→ 它读文件走自己的路由 `POST /sidebar/api/fs.read`，该路径在宿主上**未注册** → 命中 Host 兜底「非 GET/HEAD 且无匹配路由 → 405 空体」→ 客户端把非 JSON 错误体退化成裸状态码显示在预览区。
4. **触发条件**：该插件的 bundle patch **不是纯 `insert`**（自带 `disabled: !!js "…"` 表达式），而插件市场（`dsh-market` v1.66.9）**热挂载只支持纯 insert** ⇒ 变更不能热生效，只能整树重启；在没有重启的窗口里就停在半挂状态。
5. **规避口径**：启用/更新/停用该插件后，必须**完全退出并重启 WorkNexus-DSH**；市场页「1 项变更，刷新后生效」指的是浏览器半边，需点「刷新页面」与宿主对齐。

## 2. 判定链条与证据

| # | 观察 | 证据 | 结论 |
| --- | --- | --- | --- |
| E-1 | 右栏那块红字的位置/字号/颜色 | 插件 `src/client/EditorHost.tsx:611`（`editorError`）+ `src/client/sidebar.module.css:1514`（12px + error 色） | 面板是 **dsh-better-sidebar 的编辑器失败态** |
| E-2 | 文案恰为裸 `HTTP 405` | 插件 `src/client/api.ts:199`：`parsed?.error?.message ?? \`HTTP ${response.status}\`` | 响应体**不是**插件的 JSON 信封时，才退化成裸状态码 |
| E-3 | 探针：`POST /sidebar/api/fs.read` → **405 空体**；`GET /sidebar/file?…` → **404 空体**；与 `/nope` 同码 | 见 §3；对照组 `/open-in-app/open`、`/api/*` → **401**（已注册路由先过鉴权） | 插件路由**一条都没注册**（插件若在：`/sidebar/api` 非 POST 回 JSON，`/sidebar/file` 非 GET 回 403） |
| E-4 | 页面里却有插件的 tab/编辑器 | 插件 client bundle 已被页面编译（Chromium `Code Cache`，页面加载时刻 9:42）；上游 `packages/client/modules/src/index.ts:984`：`entry.fiber === undefined \|\| entry.disabled → continue` | 清单组装**只要求 entry 存在且有 fiber** ⇒ 宿主半边未激活时**客户端半边照发**，这就是「界面在、路由没在」 |
| E-5 | 市场横幅「bundle patch 含配置行/表达式，**热挂载仅支持纯 insert**，重启后生效」+ 市场日志（§4） | `~/.dsh/profiles/desktop/cordis.patch.yml`（`- id: better-sidebar` `disabled: true`）、`.dsh-market/state.json`（`"disabled":["dsh-better-sidebar"]`） | 触发条件：**patch 非纯 insert ⇒ 必须重启**；重启后该插件被保持在停用态，文件链接回到自带预览，405 消失 |

## 5. 规避口径与现象识别

1. **该插件每次变更都要「启用 + 完全重启」**：只点「刷新页面」不算；重启前热启用会失败（日志 `no loader entry matched`）。
2. **市场页的两种提示含义不同**：「刷新后生效」＝浏览器半边（点「刷新页面」）；「需重启后生效」＝宿主半边（退出应用再启动）。
3. **现象识别三条**（下次别先怀疑文件/权限）：
   - 预览区出现**裸** `HTTP 4xx/5xx`（没有「读取失败：」前缀）⇒ 先怀疑第三方侧边栏/查看器插件；
   - `/sidebar/*` 探针与 `/nope` 同码 ⇒ 宿主侧**未挂**（不是权限、不是路径）；
   - 市场页出现「需重启 / 刷新后生效」⇒ 先对齐状态再复测。
4. **临时恢复**：在插件市场停用该插件 → 重启，文件链接回到自带预览（Markdown / 文本 / PDF 可用）。
