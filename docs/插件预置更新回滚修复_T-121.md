# 插件预置更新回滚修复 — T-121

> 任务：T-121 修复三个预置市场插件自动更新回滚 ｜ 执行日期：2026-10-12 ｜ 差异集：02/10 同域扩项（DC-18）

## 1. 结论先行

1. **根因确认**：用户在插件市场点「更新」时，`dshmarket` 调官方 plugin-manager 的 `installBundle()`。
   官方 manager 在包校验通过后把同名包追加到 `dsh.profile.bundles`（`packages/boot/plugin-manager/src/index.ts`
   的 `installBundle -> selectBundle(name, true)`）。旧预置形态又在 `@worknexus/plugin-market/cordis.patch.yml`
   固定插入了同 id 行，于是每个预置插件出现两行。dshmarket 的 trial 报：
   `duplicate loader entry id "ui-skin-claude-style" (2 rows) / 重复的 loader 条目 id "ui-skin-claude-style"`，
   然后判定「更新后的组合无法启动」，自动回滚。三个插件同因，所以提示一致。
2. **修复方向回到官方通道**：预置插件本身进入 `dsh.profile.bundles`，由各自 `cordis.patch.yml` 挂载；
   `@worknexus/plugin-market` 不再固定建同 id 行。这样官方 manager 更新时只是更新同一 bundle，
   不会再追加第二行。
3. **安装态解析修复**：新机 profile `node_modules` 未物化时，bundle 层里的裸包名此前会解析失败。
   现在 `@worknexus/plugin-market` 声明三个 optional peerDependencies，把三包纳入安装态 runtime resolution；
   市场更新后 profile 本地副本存在，Node 的 profile resolution 会优先加载本地新版本。
4. **不打包**：按决策人要求，本轮只修代码和门禁，未重建安装包、未静默安装、未更新真机客户端。
