# 私有插件源与镜像（T-101）

## 1. 结论先行

1. 客户端侧 `plugins/market/src/registry/private-source.ts` 提供 `createPrivateSource(config)`：地址 / 凭据 / 超时 / 回退源可配（P6B-F01）。
2. **不可达即降级**：注册表不可达、超时、非 2xx 或响应非法时返回 `{ mode: 'installed-only', plugins: installed }`，并在 `detail` 给出脱敏原因——不影响客户端启动（P6B 验收 4）。
3. **启动路径零请求**：创建 source 不发请求（门禁断言 `not.toHaveBeenCalled`），网络行为只在 `list()` 内发生；与 §5.4 第 3 条「外部服务不可用不阻塞主界面」一致。
4. **不回退公共源**：`describe()` 固定 `fallbackToPublic: false`；与 T-100 取证结论「配置集合之外的注册表只问它自己」一致。
5. 凭据只接受官方凭据服务已解析的事实或一次性 `resolveToken()`，所有错误与描述过 `sanitizeDetail`（Token 不入日志/不回显）。
6. 控制面 `POST/GET /api/v1/market/registry` 复用 T-041 的 `ExternalService`（`service_type='plugin-registry'`）保存地址、凭据引用、超时与回退源；写操作 `kb`→`market.registry.update` 入审计，权限为**至少 admin**。
7. 裁决：私有源拉取用 `/-/v1/search?text=worknexus` 形态（npm 兼容搜索端点），并允许响应为 `plugins` 或 `objects` 两种键 — 理由是不同私有 registry 实现字段不一，客户端只做宽松归一 — 错判代价：若企业 registry 使用完全不同的协议，需要在配置层扩展适配器（未实现即降级为 installed-only，不阻塞）。
8. 裁决：新增 `ExternalService.config_json`（迁移 0006）而不是为私有源单独建表 — 理由是外部服务配置已有台账，扩展字段更小且可复用 — 错判代价：`config_json` 成为通用字段，写入方需自守「不放凭据值」的约定。

## 4. 未验证项与边界

**需真机复核（B 类）**

- B-1：真实企业私有 registry 的搜索端点与响应结构（当前用 npm 兼容形态 + 宽松归一）。
- B-2：私有源凭据经官方凭据服务的真实注入链路。
- B-3：官方管理器在真实 profile 下使用该私有源的注册表计划（T-100 B-3）。

**需外部输入（C 类）**

- C-1：企业私有 registry 地址、协议与凭据。

**超出本次范围**

- O-1：不自建镜像同步服务、不改官方注册表计划算法。
- O-2：不在启动路径同步等待外部 registry。
