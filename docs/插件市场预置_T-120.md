## 1. 结论先行

1. **`dshmarket` 已随发行版预置并真正加载到浏览器**：设置区出现「插件市场」所需的全部链路已实证 —— 行挂载（A6）、客户端半包下发（A9：`__DSH_BOOT__` 含 `dshmarket/client.js`）、包体随包（A10）。
2. **第一次交付是失败的，根因已定位（不是猜测）**：把 `dshmarket` 当作 **profile bundle** 挂载时，它自带的 `cordis.patch.yml` 用**裸包名** `dshmarket` 建行，而安装态下 Loader 的解析基址是**行所属 patch 树的目录**，Node 会沿**真实文件系统**向上找包 —— 永远到不了 `app.asar` 里的运行时，于是：
   ```
   dsh-market (dshmarket): failed to import
   ```
   实证错误：`Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'dshmarket' imported from <profile>/…`。
   **官方包能用裸包名**，是因为它们早已被宿主进程加载过、命中 Node 内部 cascaded loader 的包表；第三方包不在其中。
3. **修法是「由我们自己用显式路径建行」**：把 `dshmarket` 从 profile bundle 清单撤出（否则它自带的 patch 会把自己的裸包名行覆盖回来），改由 `plugins/market/cordis.patch.yml` 建 `dsh-market` 行，行名是相对路径 `../../dshmarket/lib/index.js`。**该形态同时被客户端模块系统支持**（`locatePkgJson` 对路径形式走 `nearestPackage(URL)` 反查最近 package.json），因此市场的客户端半包仍被正确挂到该行上。
4. **门禁自身的证明缺口一并修掉**：原 A9 只统计 `worknexus-` / `ent-core-` 前缀的失败行，`dsh-market (dshmarket): failed to import` 被漏掉、门禁**假绿**。现在改为**任何** `… failed to import` 都算失败，并新增正向断言「`__DSH_BOOT__` 含 `dshmarket/client.js`」。
5. **依赖只随包提供 `undici@7.29.0`**（`dshmarket` 声明 `^7.29.0`，而运行时自带的 8.11.2 不满足该范围）；`js-yaml` / `argparse` 由运行时自带且满足范围，**不随包重复提供**，避免 pnpm `overrides` 把上游依赖版本压到我们的副本上。
6. **出包 exit 0**（安装包 293,289,680 字节 @23:32:55），安装态 A2/A3/A5/A6/A8/A9/A10 全绿。
