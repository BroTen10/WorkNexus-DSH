## 5. 裁决记录

| # | 裁决：<决定> — <理由> — <错判代价> |
| --- | --- |
| R-1 | 用 **codeload tar.gz** 替代 `git clone`——总览 §2.1 第 2 条要求「直连 2 次 + 代理 2 次，仍失败则产出阻塞单并继续」；本次 4 次全失败，但 HTTPS 下载通道实测可用，故换通道而非判阻塞——若 codeload 通道日后失效，需回到代理方案（代价：一次网络排障） |
| R-2 | 解包用 Python + `\\?\` 长路径前缀并固化进脚本——上游含超长路径与 14 个符号链接，`tar.exe` 会报错——若用默认解包并忽略报错，后续任务会拿到不完整的树，差异集与 rebase 基线失真 |
| R-3 | 安装时设 `ELECTRON_SKIP_BINARY_DOWNLOAD=1`——Electron 二进制体积大且来自 GitHub release，本机 GitHub 通道不稳定；typecheck/lint 不需要 Electron 运行时——若后续任务需要真机运行，必须补下 Electron（已登记 B-1） |
| R-4 | tag 的 tarball 视为**基线本体**，提交 sha 由 `git ls-remote` 独立取得并登记——tarball 即该 tag 的源码快照——若两者指向不同提交（极端情况），以提交 sha 为准重新获取 |
| R-5 | 3 条 `.bin/dsh` shim 警告记为**无害**——上游 `dsh` 的 bin 指向 `lib/bin.js`（非 `.EXE`），pnpm 在 Windows 上创建 `.EXE` shim 失败属平台差异；typecheck/lint 均不受影响——若后续脚本依赖 `.bin/dsh`，改用 `node node_modules/@deepseek-ai/dsh/lib/bin.js` |
