# 预置侧边栏兼容修复（T-145）

## 1. 结论先行

复发的裸 `HTTP 405` 根因是**预置插件版本与桌面宿主 API 线不匹配**，不是文件路径、权限或预览服务故障。

DSH `0.2.1-alpha.1` 起把 Web 宿主服务 `webRuntime` 改为 `webStartup`，`alpha.2` 移除了 `webRuntime`；`dsh-better-sidebar 0.25.0` 仍注入 `webRuntime`，因此宿主半边永远 `pending`，`/sidebar/api/*` 一条路由都没有注册。浏览器侧缓存的客户端半包仍渲染编辑器，于是点文件时得到裸 `HTTP 405`。

已把预置版本提升到上游给出的 `0.2.1-rc.1+` 支持线 `0.28.0`。它改用 `ctx.connection.requestRejection`，不再依赖已删除的 `webRuntime`。当前机器与安装包均已验证为 0.28.0，宿主启动 stderr 为零。

### 裁决

- **选 0.28.0，不选降级** — 上游发布表明确 `0.2.1-rc.1+` 对应 0.28.0；0.24.1/0.25.0 仍依赖 `webRuntime`，降级不能解决 rc.2 的兼容问题 — 错判代价：继续留在 pending/405。
- **新增 `@formkit/auto-animate` 到随包闭包** — 0.28.0 新增该直接依赖，运行时树没有它；不在包集里会让离线 profile 安装或新机启动缺依赖 — 错判代价：构建成功但新机插件无法激活。
- **保留 `dsh-better-sidebar` 为预置而非移除** — 用户原工作流依赖可编辑文件预览；升级后已恢复宿主路由 — 错判代价：若后续 0.28.0 又出现运行时问题，需再按版本线降级或停用。

## 5. 复现命令

```powershell
# 1) 当前宿主端口与探针（修复后应为 403；405 表示路由仍未注册）
$ids = (Get-Process WorkNexus-DSH).Id
$port = Get-NetTCPConnection -State Listen |
  Where-Object { $ids -contains $_.OwningProcess } |
  Select-Object -First 1 -ExpandProperty LocalPort
curl.exe -s -o NUL -w "%{http_code}`n" -X POST "http://127.0.0.1:$port/sidebar/api/fs.read" `
  -H "content-type: application/json" -d "{}"

# 2) 宿主 stderr：应无 pending / did not activate
# 以安装态启动时把 stdout/stderr 重定向到临时日志，检查 stderr 为 0。

# 3) 版本与闭包
Get-Content "$env:USERPROFILE\.dsh\profiles\desktop\package.json"
python scripts\fetch_third_party_bundles.py --verify-only
python scripts\pack_presets.py --verify-only

# 4) 出包与安装
python scripts\package_desktop_win_unsigned.py
$installer = 'repos\deepseek-harness\apps\desktop\.desktop-build\targets\win-x64\unsigned-artifacts\worknexus-dsh-0.2.1-rc.2-win-x64-unsigned.exe'
Start-Process -FilePath $installer -ArgumentList '/S' -Wait
```
