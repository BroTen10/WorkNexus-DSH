# 知识库契约（T-060）

## 1. 结论先行

1. `packages/contracts/src/knowledge.ts` 交付契约⑨ `KnowledgeProvider`，覆盖需求书 §4.3.2 P3-F01 的四项能力：检索、健康检查、配置校验、权限过滤。
2. 契约版本按总览 §2.1 第 17 条与派发卡增补步骤 S2 **次版本递增**：`HOST_CORE_CONTRACT_VERSION` 由 `1.0.0` 升为 `1.1.0`，八类既有契约语义零变更，`docs/HostCore契约-v1.md` §6 变更留痕已登记。
3. 契约只定义能力面：不写 RAGFlow / AnythingLLM / http-rag 的任何端点、鉴权或构造细节，Provider 保持可替换（T-061 在此基础上实现）。
4. 权限过滤落成**双层职责**：调用方先做 `PermissionPolicy.can(actor, 'kb.retrieve', ...)` 判定（无权限不得调用 Provider，T-062 用例断言），Provider 侧按 `spaceContext` 丢弃跨空间命中。
5. 连接状态四态（`healthy` / `unreachable` / `auth_failed` / `sync_failed`）以运行时枚举 `KNOWLEDGE_HEALTH_STATES` 固化，供 T-061 与 UI 直接引用。
6. 裁决：契约版本递增取**次版本**——新增的是能力面而非字段，且 T-060 派发卡增补步骤 S2 明确要求递增次版本号；**风险**是 `verify_t029_skeleton.py` / `verify_t034_contract_doc.py` 断言的版本常量需同步更新（已同步，未放宽任何判据）。
