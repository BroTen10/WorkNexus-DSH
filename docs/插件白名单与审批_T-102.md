# 插件白名单与安装审批（T-102）

## 1. 结论先行

1. 控制面新增 `/api/v1/market/whitelist`（写=至少 admin / 读=成员）、`/api/v1/market/approvals`（请求 + 决定 + 列表）、`/api/v1/market/install`（白名单校验闸口）。
2. **企业模式**下未通过白名单的插件不能安装：`POST /market/install` 返回 403 `{reason: 'not_whitelisted'}` 并写 `plugin.install` 的 `denied` 审计（P6B 验收 2）。
3. **个人模式**不强制企业白名单：只写一次 `market.install_requested` 审计并返回 `enforced: false`（§3.5 明确要求）。
4. 审批可追踪：`plugin_approval_requests` 记录请求人 / 决定人 / 时间 / 理由；批准后自动写入白名单，随后安装放行（P6B-F03）。
5. 治理**不改官方流程**：放行结果里显式返回 `delegatedTo: '@deepseek-ai/dsh-plugin-manager'`——实际安装仍由官方管理器执行，企业侧只做判定与记录。
6. 裁决：审批粒度按「插件 + 版本」— 依据 T-102 派发卡默认裁决（审批粒度未定 → 按插件+版本范围审批）— 错判代价：同插件多版本需分别审批或走版本锁定（T-103）。
7. 裁决：兼容性声明（`dshCompatibility` / `hostCoreCompatibility`）在 T-102 允许留空，由 T-103 强制 — 理由是 T-103 才是兼容性检查的交付点，避免两个任务重复实现同一规则 — 错判代价：T-102 阶段写入的白名单可能缺声明，需在 T-103 引入时补齐（已在 T-103 用例中覆盖「缺声明被拒」）。
