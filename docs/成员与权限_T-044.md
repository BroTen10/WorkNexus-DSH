# 成员、角色与权限判断（T-044）

## 1. 结论先行

1. 服务端权威权限矩阵已落地，固定 `owner/admin/member/viewer` 四类角色和 17 个服务端动作。
2. `owner` 拥有全部能力；`admin` 可管理成员、空间、插件、审计和预算，但不能删除组织或转移所有权；`member` 只能读授权空间并创建内容/提交任务；`viewer` 只能查看授权内容与统计，不触发 Token 动作。
3. 服务端模块提供 `can()` / `require_permission()`；成员邀请、移除、角色变更和空间授权路由均写入审计。
4. 客户端 `permission-client.ts` 提供同形 UI 预判，但明确不是权威；最终以控制面裁决为准。
5. 组织治理动作 `organization.delete` 与 `ownership.transfer` 只存在于服务端扩展动作，不进入企业插件可声明的 T-030 `Action` 契约。
6. 默认最小权限已落到矩阵：未列出动作一律拒绝；没有自由组合权限点编辑器。
