## 5. 裁决记录

| # | 裁决：<决定> — <理由> — <错判代价> |
| --- | --- |
| R-1 | 包名用 `@worknexus/contracts`（T-029 派发卡口径），而非附录 B 里较旧的 `@worknexus-dsh/contracts`——派发卡优先级高于附录（附录 B 开头即声明「冲突时以派发卡为准」）——若沿用旧名，T-030/T-031 的筛选命令会全体失配（返工约 0.2 人日） |
| R-2 | 契约包**只放类型与常量**，并附「零依赖可判定」的纯函数（`hasAtLeastRole` / `summarize` / `deriveTotalTokens` / `isEnterpriseTopic`）——这些函数是契约语义的一部分（默认最小权限、只写审计、null 不猜、事件白名单），把它们放进来可以让门禁**不需要任何实现**就能验证语义——若只放类型，语义就只能靠文档约束，无法机器化 |
| R-3 | 门禁直接调用 `node node_modules/vitest/vitest.mjs` 而不经 `pnpm --filter`——pnpm 11 的 `ERR_PNPM_IGNORED_BUILDS` 门禁会让 `--filter` 路径在 esbuild 未批准时整体失败；本机用 `ignoredBuiltDependencies` 显式声明 esbuild 的构建脚本被有意忽略（vitest 实测正常）——若隐式忽略，CI 上会出现「测试没跑但看起来像环境问题」的假绿 |
| R-4 | `AgentTransport` 的负向断言改为**剥离注释后**再检测——契约文档注释里正当地写着「不实现 AgentTransport」——若不剥离，门禁会因文档而误报（本次即实际误报一次，已修正） |
| R-5 | 契约版本从 `1.0.0` 起（与附录 B 一致），且**冻结后任何变更必须留痕**（总览 §2.1 第 17 条：破坏性 → minor；新增字段 → patch）——冻结口径由 T-034 契约冻结评审正式确认 |
