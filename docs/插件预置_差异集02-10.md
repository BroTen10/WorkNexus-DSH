## 1. 结论先行

1. **三个插件随发行版预置并默认生效**：`dsh-better-sidebar@0.24.1`（右侧栏增强）、`dsh-claude-style@0.12.0`（界面皮肤）、`@linxin666/dsh-client-ui-skill-explorer@0.4.5`（技能浏览器）—— 与决策人当前实例安装的完全同版本。
2. **一条必须先讲清的坑（实测，不是推断）**：把这三个名字写进 `dsh.profile.bundles` **会装载失败** —— 隔离 DSH_HOME + 未打包构建实测三行全部报 `… failed to import`（与 T-120 的 `dshmarket` 同因：profile 层的行名解析基址是 profile 目录，第三方包只存在于运行时）。因此落地形态最终是：
   **(a)** 包随运行时（闭包根 + 锁文件钉死） → **(b)** 挂载由 `plugins/market/cordis.patch.yml` 用**显式相对路径**建行（锚定补丁文件所在目录） → **(c)** profile manifest 只登记**依赖**（插件市场以 `dependencies` 判「已安装」，因此不会再提示安装、也就不会与随包行重复挂载）。
3. **离线、可复现、可追溯**：`configs/vendor/third-party-bundles.lock.json` 由 5 条扩到 **86 条**（3 个插件 + 其完整声明依赖闭包，含 33 个 `@types/*`），每条都钉死版本 / tarball 地址 / `bytes` / `sha256`（规范化包另记 `normalizedSha256`），许可证原文逐包落盘 `configs/vendor/licenses/` 并进发行版附加声明（`WORKNEXUS-THIRD-PARTY-NOTICES.md` 3,864 → **133,913 字节**）。构建期因此**不再从 registry 拉未登记版本**（此前实测会拉到 `mermaid 11.17.2` 等漂移版本）。

## 5. 裁决记录

| # | 裁决：<决定> — <理由> — <错判代价> |
| --- | --- |
| A-1 | **挂载形态取「显式相对路径行 + 依赖登记」，不取「写进 `dsh.profile.bundles`」** — 后者实测三行全部 `failed to import`（V-3），行名解析基址是 profile 目录、第三方包只在运行时内；显式路径锚定补丁文件所在目录，实测装载成功且客户端半包下发（V-4） — 若沿用 bundle 名单，装机后三个功能全部不可用而门禁只会看到「清单里有名字」（假绿） |
| A-2 | **profile 只登记 `dependencies`（不登记 bundle）** — 插件市场以 manifest 的 `dependencies` 判「已安装」（`dshmarket/lib/profile.js::readInstalled`），登记后 Discover 不再提供安装，从而消除「再装一次 → 与随包行重复挂载」的风险 — 若不登记，市场会显示未安装，用户点击安装即可能与随包行双挂载（插件自带 patch 的聚合守卫不认识路径形式的行名） |
| A-3 | **随包含完整声明依赖闭包（86 条），不做「只带三个插件本体」** — 实测只带本体时，构建期 pnpm 会从 registry 解析并装入 `mermaid 11.17.2` 等**未登记版本**（同一份源码两次构建产物可能不同、且无许可证声明） — 若只带本体，产物不可复现且合规缺口（差异集 14 的立意）重新出现 |
| A-4 | **`@types/*` 归档按 `package-root-prefix` 规范化、scoped 包随包文件名带 scope 前缀** — DefinitelyTyped 的 `@types/*` tarball 用去 scope 包名作归档根（`d3/`），上游 `packedManifest()` 与 pnpm 都只认 `package/package.json`（实测 `prepare:packages` 报 `tar: package/package.json: Not found in archive`）；不带 scope 前缀还会与同名非 scoped 包（`d3` 与 `@types/d3`）撞文件名 — 不规范化则出包直接失败；不改名则可能静默覆盖同名 tarball |
| A-5 | **`pack_enterprise.py` 第三方随包改为默认取回**（新增 `--without-third-party`，旧开关兼容保留） — 锁文件已是发行物的第三方随包契约，且这些包都已在发行版生效；「清空 tgz 却不取回」会静默产出缺插件市场与三个预置插件的安装包（T-119 R-3 的旧理由已由 `undici` 规范化规则从根上解决） — 若沿用旧默认，一次忘记加开关就发出残包（代价：一次重出包 + 装机复核） |
| A-6 | **挂载行 id 沿用插件自身 patch 的 id**（`better-sidebar` / `ui-skin-claude-style` / `ui-skill-explorer`） — **id 是功能性标识，不是标签**：插件客户端用它派生自己的设置命名空间（`dsh-claude-style/lib/client.js` 以 `Nr="ui-skin-claude-style"` 与 `plugins.bundle.config` 拼出配置键，并按 `[entry.id, 包名, 硬编码 id]` 依次查找命名空间），插件市场也**按 id** 管理插件的皮肤与开关。**2026-10-09 现场纠正**：早先为便于对账给三行加了 `worknexus-preset-` 前缀 → 决策人真机报「ERROR：设置存储服务异常，改动不会被保存」（Claude Style 设置页），改回插件自身 id 后修复 — 若不改回，插件设置无法保存（且市场侧开关对该行无效） |
