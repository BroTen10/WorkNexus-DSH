## 1. 结论先行

1. **入口机制已落地并可被 T-050 / T-061 / T-070 / T-080 复用**：`packages/ent-entries` 提供四个企业入口的注册表、运行模式判定、按模式的增删同步，以及与插件启停的联动。
2. **个人模式是 P1 唯一分支，且行为可证**：无模式上下文时 `resolveRunMode()` 返回 `personal`；个人模式下 `syncEnterpriseEntries()` 返回 `{added: [], removed: []}`、宿主入口表为空，**不抛错**（门禁 E4 实测）。
3. **P1 不预置任何企业入口**：四个入口的 `preinstalled` 全为 `false`（门禁 E5），与「P1 只交付个人模式」一致；企业模式下拉取可见数为 4，机制完整但未启用。
4. **切换幂等可逆**：个人 → 企业 → 个人 的往返不产生重复注册、不残留入口（单测覆盖）。
5. **与插件启停联动**：插件被禁用/卸载时其拥有的入口同步注销；重新启用时按当前模式恢复。**本模块不改变插件状态**——官方 plugin manager 仍是唯一权威（门禁 E6 断言实现里无 `enablePlugin`/`disablePlugin`，且不含 `ipcRenderer`/`ipcMain`/`electron` 通道）。
6. **模式上下文留钩子给 T-035**：`RunModeContext`（`signedIn` + `organizationId`）即为对接点；批次 2 的 T-035 只需提供真实上下文，本模块逻辑不变。
