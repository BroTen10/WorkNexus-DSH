# 企业治理挂接官方插件管理器（T-032）

## 1. 结论先行

1. 企业治理只挂接官方 plugin-manager，不重写插件生命周期、不实现 enable/disable 权威逻辑、不维护第二套插件状态。
2. `createGovernanceHooks()` 提供 `onInstall` / `onEnable` / `onDisable` / `onUninstall` 四个只读治理钩子；安装钩子返回 `allow` / `deny`，启停和卸载只写审计。
3. 安装钩子内部异常和审计异常被捕获并返回 `deny`，不会冒泡进官方 plugin-manager；其余钩子的审计失败被隔离，官方行为不被阻塞。
4. `attachGovernanceHooks()` 只订阅官方 `plugin-manager/changed` 事件，返回官方 disposer；`onError` 是安全网，正常钩子内部已先行隔离。
5. 官方事件源与载荷已核验：`plugin-manager/changed` 的 `reason` 只有 `plugin | bundle | install | remove`，载荷不含插件 id / version。因此本实现把 `install` 映射为 `plugin.install`、`remove` 映射为 `plugin.uninstall`；`plugin` / `bundle` 不能判定 enable/disable 方向，统一记录为 `plugin.changed`，并把插件字段置为 `<unknown>`。
6. 上游 plugin-manager 的安装另有 `plugin-manager/install-state` 和 `plugin-manager/install-log`；后续若需要插件 id/version 的精确审计，必须补充企业安装请求关联，不能凭空补数。

## 4. 未验证项与边界

**需真机复核（B 类）**

- B-1：在发行版中触发一次第三方插件安装，确认官方流程不变、企业钩子只记录/判定。缺什么：GUI/真实安装环境和可安装的第三方 bundle。
- B-2：禁用官方 plugin-manager 后企业侧不得阻塞官方启动。缺什么：真机开关与启动日志。
- B-3：官方 `plugin` / `bundle` changed 事件与真实启停方向的关联。缺什么：官方事件载荷本身未携带方向；如需精确审计，需要企业安装请求关联。

- C-1：企业安装白名单来源与私有源策略仍未定稿；当前由调用方注入 `whitelist`。

**超出本次范围**

- O-1：不实现 enable/disable 权威逻辑、安装/卸载算法、插件状态库。
- O-2：不接管官方 `install-state` / `install-log`；精确安装审计归 P2 控制面接入。
