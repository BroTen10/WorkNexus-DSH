# 技术决策：上游桌面端承载机制核验（T-004，DG-2）

> 任务：T-004 上游桌面端承载机制核验 ｜ 批次 0 ｜ 依赖 T-001 ｜ 无人值守度 C
> 执行日期：2026-09-28 ｜ 主要证据：`apps/desktop/README.md`（108,333 B，master @ 与 `dsh-v0.2.0-rc.1` 同一提交）

## 1. 结论先行

1. **DG-2 关闭**：官方桌面端的承载机制已由上游文档明确，**我方无需设计、只需核验**。T-004 的结论是「全部核验项均有上游原文支撑」。
2. **承载链路**：Electron = 完整 dsh Web 应用的壳；`dsh-app://app/` 加载打包后的 Web 入口；应用 HTTP 请求转发到**已鉴权** Web Host；桌面默认端口 **19387**（Web 为 **3080**），可用 `webserver.config.port` 补丁覆盖。
3. **状态所有权**：Electron 在**任何 profile 访问前**取得进程级单实例锁，并**独占** `$DSH_HOME/profiles/desktop` 及其包管理状态；与 CLI 共享 `$DSH_HOME` 下的会话/设置/凭据/工作区，但**永不共享**可执行包、插件激活、lockfile、`node_modules`。
4. **插件治理边界**：Electron **不暴露任何插件管理 IPC**；插件管理走 Web 应用的已鉴权 HTTP API。任何「我方自建插件管理通道」都属越界。
5. **本任务产出「我方不得重复实现」清单 18 条**（§4），供批次 1~8 直接引用。

## 7. 对后续任务的约束

1. **T-023/T-029**：企业 bundle 预置只能写 `dsh.profile.bundles`（官方 bundle 之后），**不得**改 `packages/boot/**`。
2. **T-024**：企业入口必须走插件声明，不得改官方侧栏源码。
3. **T-026**：企业诊断上报必须是企业侧独立实现，**不得**改 `crash-report.ts` / `fatal-recovery.ts`。
4. **T-052**：插件失败隔离必须在插件内实现（同进程事实，见 S-7）。
5. **T-100~T-105**：插件治理只做白名单/审批包装，**启停唯一权威是官方 plugin manager**。
6. **通用**：任何任务若发现需要改 §4 清单中的能力，先回到 T-002 §4 判定，命中禁止项即停。
