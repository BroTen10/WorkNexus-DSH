## 1. 结论先行

1. **安装界面已换**：NSIS 品牌砖图四张（light/dark × 1x/2x）与卸载器侧栏图由**企业方标志 + `WorkNexus-DSH` 字标**重绘。画布（600×196 / 1200×392 / 164×314）、圆心与半径、字标带与卡片圆角均与上游**逐项等位**，因此安装器与卸载器的几何、DPI 分支、BMP 转换链路**零改动**（`prepare-windows-installer.ps1` 只是把新图重新合成成 BMP）。
2. **首次登录界面已换**：欢迎窗顶部整段字标 SVG（鲸鱼 + `deepseek HARNESS`）**删除**，改为「企业标志位图（40px）+ 真实文字字标」；字标取自窗口自带品牌字体变量（Montserrat）与主题变量，因此**深浅两套外观都正确**，且产品名只有一处来源（`m.welcomeBrand`，随界面语言走）。
3. **为什么不用一张新图替掉那张 SVG**：欢迎窗 `welcome.html` 的 CSP 是 `img-src 'self'`，SVG 内的 `data:` 图片会被拦；而 SVG 作为 `<img>` 渲染时同源外链图片并不可靠。改成「位图 + 文字」同时绕开这两个坑，还让主题与本地化自动正确（裁决 A-1）。
4. **顺带清掉安装器 UI 文案里的上游品牌名**（启动失败 / 应用正在运行 / 安装目录归属三条，中英各一份）——同一界面、同一类残留，一次出包解决（裁决 A-4）。
5. **素材可复现**：新增生成器 `scripts/make_brand_assets.ps1`，标志不重画、直接从品牌包 `ui-brand-official/src/client/Brand.tsx` 的 base64 单一来源解出；门禁断言「可用生成器确定性重生成且与提交内容逐字节一致」（沿用 T-021 G6 口径）。
6. **未做**：安装器窗口与欢迎窗的**真机目视**（B 类，见 §4）；本次已重出包并核验中间产物与安装包，但未截图窗口像素。

## 7. 裁决记录

| # | 裁决：<决定> — <理由> — <错判代价> |
| --- | --- |
| A-1 | **欢迎窗品牌面改为「标志位图 + 真实文字字标」，而不是重画一张整段字标图** — `welcome.html` 的 CSP 为 `img-src 'self'`（`data:` 图片会被拦，而改 CSP 属安全基线、AGENTS §3 禁止），SVG 作为 `<img>` 时同源外链图片加载不可靠；拆成「位图 + live text」同时解决 CSP、主题与本地化三件事，且名字只保留一处来源 — 若坚持单张整图：要么踩 CSP/外链两条坑，要么为浅/深主题各维护一张含字标的位图并承担字体无法栅格化（Montserrat 仅 woff2）导致的字形不一致 |
| A-2 | **安装器砖图按上游版式等位替换，不改 NSIS 几何** — 砖图是 `NSD_SetStretchedImage` 的位图资产的消费者是上游安装页代码；等位替换可让 `git diff` 只落在素材与文案上，安装器/卸载器逻辑零风险 — 若顺手调版式：等于把品牌改动扩散到安装器 UI 结构，回滚成本与验收面都变大 |
| A-3 | **生成器入库 + 门禁做确定性重生成** — 沿用 T-021 G6 的既有口径（资产必须可由脚本复现），并让标志来源与 `ui-brand-official` 保持单一来源，杜绝「安装器一套、界面一套」的漂移 — 若只提交改后的位图：素材无法复现、后续换正式素材或换字体只能重做 |
| A-4 | **一并修安装器 UI 文案里的上游产品名**（三条中英六行） — 与砖图同属「安装界面品牌差异点」，同一批出包一次解决；滞后修就要为同一界面再出一次包 — 若分两次：一轮多余出包与一轮多余真机验收（代价：多 13 行文案改动） |
