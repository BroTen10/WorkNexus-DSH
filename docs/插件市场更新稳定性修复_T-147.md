# 插件市场更新稳定性修复（T-147）

## 1. 结论先行

所有已安装插件升级都会卡住，根因不是单个插件或网络，而是 T-143 的市场预置布局：

- `dshmarket` 被物化到 `<profile>/node_modules`，却没有登记为 profile 依赖；
- 任意插件的 pnpm `remove/add` 都会把未声明包移到 `node_modules\.ignored`；
- 更新请求正由 `dsh-market` 处理时，它自己的包目录被移走，Loader 进入 `UNLOADING`；
- 旧版删除完成后，后续 `installBundle` 没有机会执行，市场日志也没有完成记录。

本次修复将市场运行时移到 `<DSH_HOME>/dshmarket`，profile 用户层改用显式相对路径
`../../dshmarket/lib/index.js` 挂载。市场依赖和官方 peer 闭包放在市场自己的
`node_modules` 下，因此任意插件的 pnpm 操作不会再触碰正在服务请求的市场。

### 裁决

- **裁决 T147-1：市场运行时移出 profile `node_modules`。** — 理由：pnpm 会清理未声明的 profile 包，问题对所有插件更新共同成立；放在 profile 外是唯一不依赖安装时序的稳定边界。 — 错判代价：市场位置从旧路径迁移一次，需要兼容旧 profile。
- **裁决 T147-2：使用显式相对路径挂载，不把市场写进 `dsh.profile.bundles`。** — 理由：保留 T-143 的市场生命周期语义，同时避免第三方裸包名在安装态无法解析；显式路径也支持客户端模块反查 `package.json`。 — 错判代价：profile 用户层多一个可读的显式路径配置。
- **裁决 T147-3：市场 peer 闭包随市场物化。** — 理由：市场移到 profile 外后，`@deepseek-ai/schemastery` 等 peer 不再能从 profile 解析；真实宿主实测缺 peer 会 `failed to import`。 — 错判代价：稳定目录增加 178 个包目录的首次复制，后续启动幂等。

## 4. 未验证项与边界

- **需真机复核（B 类）**：自动化 Windows UI 驱动在本会话不可用，因此未通过鼠标点击市场卡片；已直接调用同一官方 `removeBundle → installBundle` 路径完成安装态验证。仍建议人工再点一次市场“更新”并重启，覆盖 UI 状态轮询与重启后激活。
- **需外部输入（C 类）**：更新目标插件在 npm 上的兼容版本与发布等待期，仍由插件市场和官方宿主判定。
- **超出本次范围**：修改官方 plugin-manager 的加载、更新或恢复算法；本修复只改变 WorkNexus 的预置物化与挂载位置。
- **环境边界**：T-143 的 P9 失败来自 `WorkNexus-Enterprise` 既有脏树，本次未修改企业仓。
