## 7. 裁决记录

| # | 裁决：<决定> — <理由> — <错判代价> |
| --- | --- |
| T108-1 | **只更「由我方差异引起」的期望值；自洽夹具内的上游产品名不改** — 那 12 个文件自己构造输入与期望，断言回显夹具内容，改它们不增加行为保证，只会扩大差异集与 rebase 冲突面；门禁 P5 把「允许集合」写成枚举，新出现的越界命中会直接 [FAIL] — 若一并改，差异集凭空 +12 文件且下次上游同步要重放，收益为零 |
| T108-2 | **`tray-icon` 失败改「资产」而非改「期望」** — 上游要求 7 档位图是真实的 Windows 高 DPI 需求，我方占位 ICO 只有 32px 属实现不达标；把期望改成 `[32]` 等于用测试迁就占位资产并掩盖真实缺陷 — 若改期望，高 DPI 托盘发虚会一直存在且无人可测 |
| T108-3 | **`macos-signature` 的 `extraResources` 期望 2 → 4** — 差异集 02 已批准把两份合规文件放入 `extraResources`，期望漂移是该差异的必然结果；落点本身由 T-106 门禁 P2c 专门覆盖 — 若为「保持 2」而删断言，等于放弃对打包资源条数的检查 |
| T108-4 | **`installed-update-builder` 的偶发失败登记为环境 flake，不改期望** — 单跑 ×2 与全量复跑 ×3 均通过（9/9），失败仅出现在并发峰值；改期望会掩盖真实的竞争问题 — 若确实存在缺陷而被当成 flake 记录，代价是下次复现时定位时间变长（已在 §4 B-1 登记复现条件） |
| T108-5 | **期望值更新单独登记为差异集 07，而不是拆进 01/02/03 三条补丁** — 这些改动由三条差异共同引起，拆分会把同一批测试资产切碎到三个补丁里、rebase 时更难核对；单独一条「桌面壳测试期望同步」边界清晰、可整批回放 — 若拆分，代价是补丁与「谁触发了它」的对应关系需要在文档里额外维护 |
