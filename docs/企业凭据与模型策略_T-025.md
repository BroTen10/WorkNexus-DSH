## 1. 结论先行

1. **凭据一律复用官方凭据缝**：企业侧唯一允许的凭据输入是**布尔事实**
   （`resolveCredentialFact({ hasUsableCredential, credentialRefs })`），来源标记恒为
   `official-credentials-service`；**密钥值、非布尔值、未知键一律拒绝**（fail closed），
   未知键拒绝使「顺手把 `apiKey` 塞进来」在类型层就不可能。
2. **无第二套凭据存储**：企业侧代码（`packages/**`、`bundles/**`、`plugins/**`）不含
   `credentials.yaml` / `.credentials.*` / `keytar` / `safeStorage` / `wincred` / DPAPI /
   `createCipheriv` 任何痕迹，且企业 bundle 内**没有任何落盘写入调用**（门禁 M2 双断言）。
3. **模型策略只做「预置默认 + 可下发清单」**：`resolveModelPolicy()` 的层优先级为
   **space > organization > 预置默认**，再按官方可用模型清单过滤；结果里 `blocked` 恒为 `false`。
4. **不可用即回落，不阻塞会话**：清单为空、默认模型不在清单内、策略层非法（非对象/含未知键）
   三种情形都回落官方默认行为并给出 `reason`；**任何情形都不阻塞会话**（门禁 M4 逐条实测）。
5. **不接管官方模型配置页**：本次对上游**零代码改动**（差异集仍为 T-021 的 11 条品牌条目），
   模块不注册 UI / IPC / 路由，自述字段 `takesOverOfficialModelSettings: false`。
6. **模块零副作用并已真实装配**：`apply()` 为空实现（不注册服务、不订阅事件、不落盘、不联网）；
   作为 bundle 的第三行 `ent-core-model-policy` 被参照 dsh 装配进组合树（门禁 M7 实测）。
7. **真机项未做（B 类）**：卡片要求的「配置真实 Provider → 模型可切换 → Key 不出现在明文日志」
   需要 GUI 会话 **与** 一枚真实 Provider Key；本机两者都不具备，且「写入真实密钥」属凭据操作、
   不在本次授权范围。按派发卡裁决，凭据部分标注 **待人工复核（B）**。

## 4. 未验证项与边界

**需真机复核（B 类）**

- B-1：**真实 Provider 下的模型可切换 + Key 不出现在明文日志**（派发卡 Step 3）。缺什么：GUI 会话 +
  一枚真实 Provider Key（写入真实密钥属凭据操作，未获授权）。怎么补：人工在真机配置一个真实 Provider，
  切换模型并发起一次真实会话，然后 `Select-String` 扫描应用日志与 `$DSH_HOME` 下配置文件确认无
  `sk-` 明文。影响哪条验收：P1-F10 / P1-F14 的「我方补充部分」真机半句。
- B-2：**官方凭据服务不可用时的实际降级表现**。本模块已按裁决实现「只做默认模型与策略文档」的降级，
  但真实「官方凭据缝不可用」场景未构造。缺什么：可控的故障注入环境。怎么补：真机拔掉凭据后观察
  `hasUsableCredential=false` 时官方配置页是否仍可用（本模块不介入，预期不阻塞）。
- B-3：**space / organization 层的真实下发通道**。本次只交付纯函数与层优先级；真正把策略下发到客户端
  需要控制面（归 T-040）与模式上下文（归 T-035）。

**需外部输入（C 类）**

- C-1：**企业允许/默认可用的模型清单取值**（当前预置 `deepseek-chat` / `deepseek-reasoner` 为占位）。
  缺什么：业务与成本决策。怎么补：由决策人给定后改 `DEFAULT_MODEL_POLICY` 或经下发层覆盖。
  影响哪条验收：P1-F10 企业模型策略的最终取值。
