# 技术决策：部署拓扑与插件边界（T-011，DG-7 / DG-8）

> 任务：T-011 部署拓扑与插件边界 ｜ 批次 0 ｜ 依赖 T-004 ｜ 无人值守度 A
> 执行日期：2026-09-28

## 1. 结论先行

1. **DG-7 第一版拓扑定稿：单机部署**——Electron 壳 + 官方 dsh runtime（同进程 Host）+ **本机企业控制面（FastAPI）** + **本机 PostgreSQL 17 容器**。局域网 / 私有云形态**留待 P2 收尾前再确认**。
2. **DG-8 定稿：企业字段只在企业侧读取**。官方客户端**不需要理解任何企业字段**；企业侧通过 Host Core 契约获取上下文，官方侧零感知。
3. **边界表覆盖需求书 §3.2 全部八类契约**（IdentityContext、SpaceContext、PermissionPolicy、AuditSink、UsageLedger、EventBus、PluginGovernanceView、UpdateManager），逐条给出「归属 / protected / host-infrastructure / 插件可见性」。
4. **个人模式不部署控制面**（§3.5）：P1 只交付个人模式，控制面自 P2 起启用。
5. **`protected` 的强制力未获证实**（见 T-005 实测）：本表把 `protected` / `host-infrastructure` 作为**声明性标注**登记，**不得声称有 Loader 级强制**。

### 3.2 边界字段表（DG-8，覆盖 §3.2 八类契约）

字段含义：

- **归属**：`官方基线`（上游实现，我方不碰）/ `Host Core`（我方宿主契约层，随发行版预置）/ `企业插件`（业务侧）。
- **保护标记**：`protected` / `host-infrastructure` 为**声明性标注**（T-005 未证实其 Loader 强制力）。
- **插件可见性**：其他企业插件能否读取该契约。

| 契约（§3.2） | 能力项 | 归属 | 保护标记 | 插件可见性 | 官方侧是否可见企业字段 |
| --- | --- | --- | --- | --- | --- |
| **IdentityContext** | 当前用户、登录态、邮箱、组织归属 | Host Core | `host-infrastructure` | 只读（企业插件可读） | **否** |
| | 官方身份（匿名关联 id、API key 存在性） | 官方基线 | — | 只读镜像 | — |
| **SpaceContext** | 当前组织、部门、项目空间 | Host Core | `host-infrastructure` | 只读 | **否** |
| **PermissionPolicy** | 「用户能否对某资源执行某操作」判定 | Host Core | `protected` | 只读（调用判定，不可改规则） | **否** |
| **AuditSink** | 写入操作审计事件 | Host Core | `host-infrastructure` | **只写**（不提供读） | **否** |
| **UsageLedger** | Token / 模型 / 会话 / 用户 / 空间 / 成本 | Host Core | `host-infrastructure` | **只写**（读走控制面） | **否** |
| **EventBus** | 企业事件命名空间 + 订阅白名单 | Host Core（**复用官方事件机制**） | `host-infrastructure` | 订阅（白名单内） | **否** |
| **PluginGovernanceView** | 官方插件状态只读镜像 + 白名单/审批判定 + 插件事件转审计 | Host Core | `protected` | 只读 | **否**（官方 plugin manager 仍是启停唯一权威） |
| **UpdateManager** | 版本锁定口径、跟随策略、差异集状态、rebase 记录 | Host Core（**更新与回滚由官方实现**） | `host-infrastructure` | **不暴露**（仅控制面/发行侧） | **否** |

### 3.3 企业字段与官方命名的隔离规则

| # | 规则 | 依据 |
| --- | --- | --- |
| N-1 | 企业字段独立命名空间，**不覆盖官方** `identity` / `credentials` / `api` 语义 | 总览 §2.1 第 13 条 |
| N-2 | 必要时加 `ent` 前缀（如 `entOrganizationId`、`entSpaceId`） | 同上 |
| N-3 | 官方插件不得读取企业字段（无反向依赖） | DG-8「企业字段只在企业侧读取」 |
| N-4 | 企业侧不得把企业 Token 注入官方会话链路 | 需求书 §3.3 |
| N-5 | 企业侧不得复制官方会话数据；`SessionMeta` 只存企业元数据 | 需求书 §6.1 补充 |

## 4. 裁决记录

| # | 裁决：<决定> — <理由> — <错判代价> |
| --- | --- |
| R-1 | 第一版采用**单机部署**（控制面与客户端同机） — DG-7 卡片建议 + 总览 §2.1 第 9 条（控制面用 Docker PG17）；降低首版集成复杂度 — 若客户实际要求多机，控制面本身是 REST 服务，迁移只涉及地址与网络配置（代价约 0.5 人日） |

| R-3 | `protected` / `host-infrastructure` 只作**声明性标注**，不声称强制力 — T-005 实测未观察到 Loader 级保护；声称强制力会形成虚假保证 — 若后续上游提供强制保护，只需收回本声明（文档改动，无代码返工） |
| R-4 | 企业字段独立命名空间，官方侧零感知 — DG-8 + 总览 §2.1 第 13 条 — 若混入官方命名空间，上游升级会覆盖或冲突 |
| R-5 | 官方 api-gateway 与企业控制面**双通道并存**，互不接管 — 需求书 §3.3 明确 | 若合并，会突破「不接管官方会话链路」的硬约束 |

## 5. 未验证项与边界

**需真机复核（B 类）**

- B-1：单机部署下控制面与客户端的实际端口共存（19387 / 3080 / 控制面自定义端口）。
- B-2：控制面不可达时的降级体验（需 P2 实现后验证）。

**需外部输入（C 类）**

- C-1：**局域网 / 私有云形态**（P2 收尾前确认）。缺什么：客户部署要求。怎么补：P2 收尾前列为决策项。影响哪条验收：§4.2 部署相关条目。
- C-2：控制面的实际监听地址与端口分配（需在 `services/api/.env.example` 定稿时确认，见总览 §2.1 第 9 条）。
- C-3：外部依赖（RAGFlow / DocGraph）的部署归属——客户侧自有还是本方代管。

**超出本次范围**

- O-1：不实现控制面（归批次 3）。
- O-2：不做网络与安全加固设计（HTTPS、反向代理等）。
