1. **决策人环境已切到 hub 并用它跑通**：`~/.dsh/profiles/desktop/cordis.patch.yml` 增加一条 pi-ai 自备路由（`enterprise-hub`）+ 默认模型 `deepseek-v4.1-flash`；密钥走官方凭据引用 `ENTERPRISE_HUB_API_KEY`（值在 `~/.dsh/.credentials.yaml`，仓库与 profile 文件零密钥）。决策人真机复核回执：重启客户端后模型选择器可见「企业方 Hub / DeepSeek-V4.1-flash」且新会话默认即它（**B-1 已结案**）。

## 附：裁决记录

- **裁决 R-1：默认路由走 `llm-pi-ai` 的 `anthropic-messages`（而不是原生 `llm-deepseek`）** — 理由：hub 的 Messages 端点接受 DSH 的工具 schema，而原生适配器的严格 SSE 校验会被 hub 的重复 `message_start` 打断（V-4）；`openai-completions` 又被 hub 的工具 schema 校验拦住（V-5）。**错判代价**：多一层 pi-ai SDK；若 hub 修好重复帧，可回到原生接法（少一层、还带 Files API 与 wire extensions）。
- **裁决 R-2：缺失即补（启动路径 `applyRelease()`），而不是只在建 profile 时种** — 理由：与差异集 10 既有形态一致，「发行版默认」的含义是未表达过意见的机器都走它；用户层出现任一自有行即完全不动。**错判代价**：老机在其用户未表达意见时会切到 hub，且该机若无 hub key 则默认模型在填 key 前不可用（恢复方式见 §5 第 5 条）。
- **裁决 R-3：密钥只写引用名（方案 A）** — 理由：决策人 2026-10-15 选定；仓库与公开脱敏镜像零凭据。**错判代价**：新机多一步人工填 key；若改选出包期注入需新增打包步骤与「不覆盖用户已改 key」规则。
- **裁决 R-4：不新开差异集条目，扩项落在 02/07/10** — 理由见 DS-14（新条目会把条目数 120 推到 121，牵动 7 处门禁计数）。**错判代价**：三个条目的「职责描述」略有膨胀；日后模型路由补齐若独立演进需拆条目并同步计数。
- **裁决 R-5：上游 spec 只就地更新 3 处期望、不新增用例** — 理由：`verify_t108_client_regression.py` 的 P4c 明令「用例声明未增删」；新行为探针统一放本任务门禁（tsx 直连真实模块）。**错判代价**：新行为的回归保护依赖门禁被跑；若门禁被跳过，spec 侧看不到该行为。
