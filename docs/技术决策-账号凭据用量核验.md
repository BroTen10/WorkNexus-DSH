# 技术决策：账号 / 凭据 / 用量能力核验（T-006，DG-3）

> 任务：T-006 账号、凭据与用量能力核验 ｜ 批次 0 ｜ 依赖 T-004 ｜ 无人值守度 B（含真机 GUI 项）
> 执行日期：2026-09-28 ｜ 证据：上游 `apps/desktop/README.md` + 本机上游包 README（`dsh-credentials`、`dsh-credentials-local`、`dsh-token-meter`、`dsh-api-account-controller`）

## 1. 结论先行

1. **账号登录当前不可用**：上游 `apps/desktop/README.md` 的 Known limitations 原文——**"Account sign-in is not connected; the Sign in button is disabled."** 这与「可登录看余额用量」的说法**直接冲突**，本任务按上游原文采信。
2. **但登录链路已被完整设计并实现到「已设计未接通」**：README 描述了 system-browser PKCE 登录、Host 侧临时 loopback 回调、凭据先落盘再进工作区、`dsh://open` 回流等完整流程。**结论：机制在，开关未接通**——我方**不得**自行实现第二套登录。
3. **凭据服务边界明确**：官方 `@deepseek-ai/dsh-credentials` 是唯一凭据缝（seam），本地实现 `@deepseek-ai/dsh-credentials-local` 落盘到 `<harness home>/.credentials.yaml`。**企业侧只能复用，不得另立第二套密钥存储**（需求书 §11；总览 §2.1 第 13 条）。
4. **凭据文件的硬边界**：文件只有 OS 用户可读，但**agent 工具进程以同一用户运行**——上游原文明确「a deployment that must keep provider keys away from its own agent cannot get there with file permissions」。**因此企业侧不得把「密钥对 agent 保密」当作安全承诺。**
5. **用量来源按 DG-3 优先级落地**：
   - ①官方 session 投影 **可得**（`dsh-token-meter` 提供 `tokenUsage` / `contextPressure` / `contextBreakdown` 三个投影单元）；
   - ②官方账号用量能力 **当前不可达**（登录未接通）；
   - ③官方 telemetry **未核验**（本任务未取证）。
   按总览 §2.1 第 3 条：**用量来源降级为「官方 session 投影」；缺失字段留空或标 `adapter_estimate`；禁止填假数。**
6. **计量精度声明**：官方投影是**近似值不是账单**——上游原文：「Occupancy is a reference figure, not a billing record」「The fixed heuristic is approximate… not an exact provider tokenizer」。需求书 §6.3 的 `estimated_cost` 属**估算**，必须标 `adapter_estimate`，不得宣称与账单一致。

### 3.3 用量来源逐字段判定（Step 3）

对照需求书 §6.3 字段表，按三条来源逐一判定。图例：**可得** / **估算** / **不可得**。

| 需求书 §6.3 字段 | ①官方 session 投影 | ②官方账号用量 | ③官方 telemetry | 结论与来源标注 |
| --- | --- | --- | --- | --- |
| `usage_id` | 企业侧生成 | 无 | 无 | 企业侧生成 UUID ｜ `source=dsh_event` |
| `timestamp` | 会话事件时间戳 | — | — | **可得**（事件时间） |
| `organization_id` | 无（官方无组织概念） | 无 | 无 | 企业侧上下文注入 |
| `space_id` | 无 | 无 | 无 | 企业侧上下文注入（可为 `null`） |
| `user_id` | 无 | 无（仅有匿名关联 id） | 无 | 企业侧上下文注入 |
| `session_id` | 官方会话 id | — | — | **可得** |
| `plugin_id` | 归因需企业侧 | 无 | 无 | 可为 `null` |
| `provider` | 请求 envelope 的 provider | 无 | 未核验 | **可得**（来自 `request/header`） |
| `model` | 同上 | 无 | 未核验 | **可得** |
| `prompt_tokens` | `tokenUsage.uncachedInputTokens`（+ 缓存读写另计） | 不可达 | 未核验 | **可得但非账单级** |
| `completion_tokens` | `tokenUsage.outputTokens` | 不可达 | 未核验 | **可得** |
| `total_tokens` | 由上述推导 | 不可达 | 未核验 | **可得（推导）** |
| `cache_read_tokens`（需求外，投影提供） | `tokenUsage.cacheReadTokens` | 不可达 | 未核验 | **可得**（建议保留） |
| `cache_write_tokens`（需求外，投影提供） | `tokenUsage.cacheWriteTokens` | 不可达 | 未核验 | **可得**（建议保留） |
| `estimated_cost` | **不可得**（投影明确「not a billing record」） | 不可达 | 未核验 | `null`，或按企业单价表算 `adapter_estimate` |
| `source` | — | — | — | 允许值：`dsh_event` / `adapter_estimate` / `manual_import` |

**投影语义要点（供 T-047 实现直接引用）**：

| 投影键 | 字段 | 语义 |
| --- | --- | --- |
| `tokenUsage` | `uncachedInputTokens` / `outputTokens` / `cacheReadTokens` / `cacheWriteTokens` | 完整 durable log 的用量；最终 assistant 消息样本会替换同一 attempt 的流式用量；`llm/retry-started` 结束该替换作用域 |
| `contextPressure` | `pressureTokens` / `projectedTokens` / `contextWindow` | 可选；`pressureTokens` 为最近一次 provider 上报的 prompt 大小 |
| `contextBreakdown` | `systemTokens` / `toolsTokens` / `messageTokens` | **启发式构成，不是计费**；三者之和等于 `measure().nodes[].heuristicTokens` |
| 单轮精确用量 | `deriveTurnTokenUsage(events)` | 折叠一个完整 turn 的精确 per-attempt 与整轮用量；**证据不足时返回无结果**（不得编造） |

**精度与边界（必须写进企业侧 UI）**：

1. 固定启发式是 **4 字符/词元** 量级，**CJK 与 JSON Schema 会明显低估**。
2. provider 上报用量**仅在 canonical request envelope 完全一致时**才复用；否则整体启发式估算。
3. 官方明确：「nothing in the harness makes decisions from it」——占用率是**参考值**。
4. 因此企业侧展示必须标注「估算值」，并在缺字段时留空。
