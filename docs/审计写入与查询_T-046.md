# 审计事件写入与查询（T-046）

## 1. 结论先行

1. 审计服务使用固定动作白名单，覆盖需求书 §6.2 的九类事件族：认证、组织/部门/空间、成员与角色、插件、知识库、DocGraph、预算和客户端版本升级。
2. 审计只追加：服务层没有 update/delete；路由层没有 PATCH/PUT/DELETE。更正通过 `POST /audit/corrections` 追加新事件并携带 `correctsEventId`。
3. 审计查询和导出仅限组织 `owner` / `admin`；导出行为本身写入 `audit.export`。
4. 清理/归档审批仅 `owner` 可触发；当前实现记录批准事件，包括范围、涉及条数和原因，不在默认 3 年留存期内物理删除。
5. `POST /audit/events` 是客户端只追加接收端；服务端生成 `eventId` / `timestamp`，并默认留存 1095 天。
6. 宿主侧 `createHttpAuditSink()` 实现 T-030 `AuditSink` 契约，只提交原始事件，不本地生成 ID/时间戳。
