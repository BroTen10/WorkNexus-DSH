# 引用展示与检索日志（T-064）

## 1. 结论先行

1. `plugins/knowledge/src/citations.tsx` 交付 `<Citations>`：每条引用保留 `documentId`、`title`、`snippet`，有链接时渲染可点击 `url`，满足 P3-F06「可追溯到文档、片段或链接」。
2. 引用组件使用官方 Web 端的 **React 18** 组件形态（与上游 `react@^18.2.0` 同源），不引入第二套设计系统；视觉样式跟随官方主题（B 类真机项）。
3. 空引用渲染显式占位「无引用」；渲染自动转义 HTML（用例断言 `<script>` 被转义），缺 `documentId` 的脏命中被丢弃。
4. 控制面新增只追加表 `knowledge_retrieval_logs` 与接口 `/api/v1/knowledge-retrieval-logs`：记录**请求摘要哈希与长度、命中数量、知识库 ID、用户、空间、耗时**（P3-F08）。
5. 隐私边界：日志**不保存查询正文，也不保存文档正文**——落库前把查询转成 `sha256` 十六进制与长度；测试断言响应与列表都不含查询原文（与 §7.1 同源的「白名单 + 不留正文」口径）。
6. 只追加：日志没有更新/删除接口；留存沿用 §4.2.4 规则（`retention_days` 默认 1095 天 + `retain_until`）。
7. 权限：写入需组织成员（检索者自行上报）；读取收敛到**至少 admin**（管理视图）。
8. 裁决：日志保留查询摘要而不保留明文 — 理由是既满足「记录检索请求」又可回放同一查询且不引入正文留存风险 — 错判代价：无法直接从日志读出查询原文，排查需配合调用方日志或重新发起检索。
9. 裁决：`0004` 迁移沿用 `Base.metadata.create_all` 形态（与 0002 一致），在全新库与已升级库上都幂等 — 理由是与既有迁移风格一致、只创建缺失表 — 错判代价：若将来需要精确的表结构快照迁移，需把 0002~0004 逐步替换为显式 DDL。
